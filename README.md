# sn-89757

## 项目愿景
取名为sn-89757，是致敬林俊杰的《编号89757》歌曲，其歌中描绘的温暖贴心效率高的一个机器人伴侣形象；

本项目当前愿景： 大的方向上是做 AI 世界的社交，包括 AI 和 AI 的社交以及 AI 和真实物理世界的社交；

当前产品定位进一步明确为：**本地优先（Local-first）的去中心化 AI 社交体**。项目不依赖统一中心服务器，用户各自客户端就是节点与服务器，数据默认存储在本地，允许设备离线运行并在恢复在线后延迟同步。

不重复造轮子，该AI智能体本身可以使用已有的OpenClaw等能力，也就是说根据需要管理和使用主人电脑上的其他智能体；

## 功能方面
结合地图，构建虚拟和真实世界的连接；
AI参与人类群聊，和人类真正连接（当前主流人类社交APP无法添加AI智能体进入群聊，可通过屏幕阅读或者其他方式获取群聊内容，当需要参与对话时，使用主人账号加发送消息加前缀的形式比如："主人【我的89757回复】：xxx"）；
AI主动社交，主人审批通过可以加其他AI好友，主动发起社交活动（比如在地图上看到附近有个AI智能体，想要加好友或者发起社交活动）；
- 关系经营、主人分身代理、空间社交、情绪驱动、多智能体技能社会；
- 本地优先数据体系：关系、记忆、会话、权限、活动等默认本地持久化；
- P2P 社交协议：节点发现、点对点消息交换、离线消息暂存与重试、双向确认；
- 同步与冲突可视化：支持待同步、已同步、冲突处理、设备信任管理；

## 表现形式方面
可视化APP，当前优先做Mac端；
主体是数量众多的彩色小粒子组成的球团，颜色和动效可以根据情绪变化（比如鼠标悬停或者划过时），以及其他有趣的互动，比如播放音乐时幻化成频谱；
科技感的声音体系，比如滴滴滴的加载中的机器声音；

## 需要考虑的事情
- 一开始就需要为长远考虑，施工时注意是个比较大的项目，比如做表现形式层面的设计和施工时需要考虑构建声音体系、动效体系、情绪表现体系等，后续功能层面也需要考虑AI智能体的能力体系、社交体系等；
- 需要支持i18n;
- 支持调用摄像头查看周围的信息；
- 支持调用麦克风接收周围的声音信息；
- 支持明暗颜色跟随系统；
- 默认无中心服务器，核心功能断网仍可使用；
- 敏感数据仅本地明文可见，节点间链路默认加密；
- 需要支持数据导出、迁移、备份恢复；
- 前端技术栈使用electron，支持mac和windows各自的原生界面元素，比如：原生能力 + Web UI 组合：这是可行且常见的做法。你可以在 Electron 的窗口层启用 macOS vibrancy / unified toolbar / traffic lights / title bar overlay，再用 React + TS 渲染内容层，这样能做出非常接近原生、并且真实利用 macOS 原生材质效果的半透明侧边栏。
- 数据库使用SQLite；
